# 🔐 Инструкции по безопасности

## ✅ Реализованные меры безопасности

### 1. **Защита конфигурационных файлов**
- ✅ `.htaccess` блокирует доступ к `config/database.php`, `.env` файлам
- ✅ `.htaccess` блокирует доступ к `.bak`, `.sql`, `.ini`, `.log` файлам
- ✅ Опция `-Indexes` запрещает просмотр содержимого директорий

### 2. **Защита загрузок файлов**
- ✅ `uploads/.htaccess` запрещает выполнение PHP скриптов
- ✅ Проверка MIME типов при загрузке (finfo)
- ✅ Ограничение размера файлов (5MB для изображений, 50MB для видео)
- ✅ Генерация уникальных имен файлов (uniqid + timestamp)

### 3. **Защита от SQL инъекций**
- ✅ Использование PDO с prepared statements
- ✅ PDO::ATTR_EMULATE_PREPARES = false для реальных prepared statements
- ✅ Валидация ID (функция validateID)

### 4. **Защита от XSS**
- ✅ Функция `escape()` для всех выводов в HTML
- ✅ Заголовок `X-XSS-Protection: 1; mode=block`
- ✅ Заголовок `X-Content-Type-Options: nosniff`
- ✅ `htmlspecialchars()` с ENT_QUOTES

### 5. **Защита от CSRF**
- ✅ CSRF токены для всех форм
- ✅ Функции `generateCSRFToken()` и `verifyCSRFToken()`
- ✅ Проверка токенов при авторизации
- ✅ Логирование неверных CSRF токенов

### 6. **Rate Limiting**
- ✅ Ограничение попыток входа (5 попыток за 15 минут)
- ✅ Автоматическая блокировка при превышении лимита
- ✅ Логирование превышений лимита

### 7. **Защита сессий**
- ✅ `session.cookie_httponly = 1` (защита от XSS)
- ✅ `session.use_only_cookies = 1`
- ✅ `session.cookie_samesite = Lax` (защита от CSRF)
- ✅ Проверка IP и User-Agent при каждом запросе
- ✅ Регенерация ID сессии каждые 30 минут

### 8. **Защита паролей**
- ✅ `password_hash()` с bcrypt алгоритмом
- ✅ `password_verify()` для проверки
- ✅ Никаких дефолтных паролей в коде

### 9. **CORS политика**
- ✅ Разрешены только проверенные домены
- ✅ Запрет `Access-Control-Allow-Origin: *`
- ✅ Включен `Access-Control-Allow-Credentials`

### 10. **Дополнительные заголовки безопасности**
- ✅ `X-Frame-Options: SAMEORIGIN` (защита от clickjacking)
- ✅ `Referrer-Policy: no-referrer-when-downgrade`

### 11. **Логирование**
- ✅ Все попытки входа логируются
- ✅ Подозрительная активность записывается в `logs/security.log`
- ✅ Логи защищены от веб-доступа

## ⚠️ ВАЖНЫЕ ДЕЙСТВИЯ ПОСЛЕ УСТАНОВКИ

### 1. **Создайте .env файл**

```bash
cp .env.example .env
nano .env
```

Заполните реальные данные:
```env
DB_HOST=localhost
DB_NAME=confectionery_fireshow
DB_USER=ваш_пользователь_БД
DB_PASS=ваш_надежный_пароль_БД
```

### 2. **Смените пароль администратора**

Зайдите в админ-панель и смените дефолтный пароль:
```
Логин: admin
Пароль: admin123 (СРОЧНО СМЕНИТЕ!)
```

### 3. **Настройте HTTPS**

Раскомментируйте в `.htaccess`:
```apache
RewriteCond %{HTTPS} off
RewriteRule ^(.*)$ https://%{HTTP_HOST}%{REQUEST_URI} [L,R=301]
```

И обновите в `config/security.php`:
```php
ini_set('session.cookie_secure', 1); // Вместо проверки
```

### 4. **Добавьте свой домен в CORS**

В `api/chat.php` добавьте свой домен:
```php
$allowed_origins = [
    'https://ваш-домен.com',
    'http://ваш-домен.com'
];
```

### 5. **Установите права на файлы**

```bash
# Права на директории
chmod 755 /path/to/project
chmod 755 /path/to/project/uploads
chmod 755 /path/to/project/logs

# Права на файлы
chmod 644 /path/to/project/*.php
chmod 644 /path/to/project/.htaccess

# Защита конфигов
chmod 600 /path/to/project/config/database.php
chmod 600 /path/to/project/.env
```

### 6. **Настройте резервное копирование**

Создайте cron задачу для бэкапа БД:
```bash
crontab -e
```

Добавьте (бэкап каждую ночь в 3:00):
```
0 3 * * * mysqldump -u USER -pPASS confectionery_fireshow > /path/to/backups/db_$(date +\%Y\%m\%d).sql
```

### 7. **Мониторинг логов безопасности**

Периодически проверяйте:
```bash
tail -f logs/security.log
```

Ищите:
- Частые неудачные попытки входа
- CSRF ошибки
- Rate limit превышения

## 🚨 Что делать при взломе

1. **Немедленно:**
   - Смените все пароли (БД, админ, FTP, хостинг)
   - Проверьте файлы на наличие вредоносного кода
   - Заблокируйте подозрительные IP

2. **Проверьте:**
   ```bash
   # Ищите подозрительные файлы
   find . -name "*.php" -mtime -7

   # Ищите base64 код (часто используется хакерами)
   grep -r "base64_decode" .

   # Проверьте логи
   tail -100 logs/security.log
   ```

3. **Восстановите из бэкапа:**
   - База данных
   - Файлы проекта

```bash
# Найти файлы с подозрительными правами 777

# Проверить владельца файлов

grep -r "eval(" .

```
